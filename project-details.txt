# Autonomous AI Travel Planning Agent - Project Overview

## 1. Project Structure & Architecture
The AI Travel Planning Agent is a full-stack application leveraging a Python/FastAPI backend powered by LangGraph for agentic workflow orchestration, and a React frontend for the user interface.

### Backend (`src/ai_travel_agent`)
- `api/main.py`: The FastAPI entry point. Exposes REST endpoints (e.g., `/health`, `/export`) and a WebSocket route (`/ws/plan`) for streaming real-time planning progress to the UI.
- `agents/graph.py` & `nodes.py`: The core LangGraph state machine. It orchestrates a multi-step pipeline (parse -> budget -> flights/hotels/attractions -> geo clustering -> route optimization -> evaluate -> PDF/Map generation).
- `tools/`: Interfaces with external APIs (SerpApi for flights/hotels, OpenWeatherMap for weather, OSRM for travel times).
- `optimizer/itinerary_builder.py`: The core logic that assembles a multi-day itinerary based on the agent's findings, checking for time and budget conflicts.
- `services/`: Contains specialized generators (e.g., `travel_map_generator.py` for Folium maps, `pdf_renderer.py` for PDF exports).
- `utils/`: Contains monitoring (Prometheus), logging (structlog), caching (Redis), and LLM cost tracking utilities.

### Frontend (`frontend/`)
- Built with React, Vite, and Tailwind CSS (or similar styling).
- Uses `react-leaflet` to display the interactive travel map.
- Connects to the backend via WebSockets (`/ws/plan`) to stream progress bars and chat responses.

## 2. Main Functions
- `plan_trip` (WebSocket flow): Receives a user prompt like "Paris 5 days culture and food under $3000", parses it via an LLM, and begins executing the LangGraph nodes.
- `_stream_graph`: The async generator that steps through the LangGraph state machine, yielding progress updates ("Searching flights...", "Optimizing routes...") back to the frontend.
- `build_itinerary`: LangGraph node that attempts to slot attractions and meals into a physical daily schedule.
- `optimize_routes`: Week 10 feature that solves the Traveling Salesperson Problem (TSP) using a Distance Matrix to reorder activities optimally.
- `evaluate_budget`: Week 12 feature that acts as a "Judge" LLM to ensure the final itinerary is logical and under budget.

## 3. Testing Commands (Weeks 10 - 19)

I have successfully verified that the frontend and backend are both running properly. You can test each specific week's components using the commands below. Ensure you are in the project root (`d:\study\ai-travel-agent`) when running these commands.

**Week 10: Route Optimization (TSP Solver)**
